## Behavior

- `isActive` is shared-directory availability, not tenant targeting, purchase status, or recent engagement. Account Master activates matching accounts and deactivates absent linked official accounts. Manual workflows can also activate accounts. This change removes active status from the wholesale-name import rule; it does not redefine active status.
- Account Master seeds a new account's name from OHLQ, then leaves its existing name untouched on every subsequent import. This includes inactive/reactivated accounts and existing placeholder names. A platform administrator can still manually rename an account.
- Independent `addressImportProtected`, `cityImportProtected` and `zipImportProtected` booleans preserve the current field value, including null. Editing only one field does not freeze the other two. An unrelated save never writes a false protection flag. Later manual changes remain possible and retain protection.
- The migration protects differences from a linked stored raw `Account` row, including a cleared canonical value against a populated source value. Differences are evidence of divergence, not proof of a manual author. For known user-created accounts without an official link, populated fields are protected; missing fields can be filled later. Merged tombstones are excluded from the backfill.
- Raw official `Account` records continue refreshing with OHLQ values. County, phone, agency, district, delivery day, ownership and state retain their prior import policy. Agency CSV and sales-status automation are outside this change.
- The actual Account Master UPDATE resolves protection against the locked current database row, never assigns `name`, and never clears a protection flag. An edit/rename saved after preflight survives. Geocodes reset only when the resulting normalized public address changes; casing/punctuation-only changes retain coordinates. A concurrently merged account aborts its update rather than mutating a tombstone.
- Official relinking respects protected blanks. Manual creation paths protect entered address fields. Merges prefer protected destination values, otherwise transfer protected source values and flags, including blanks; both-protected conflicts keep the chosen destination. The merge invalidates the geocode if its resulting address changes. Target-workbook imports also respect protected blanks and leave existing names untouched.
- No automatic unlock or reset-to-OHLQ control was requested. These protections remain set through later edits/imports. Corrections already overwritten before the migration are not recoverable from the current canonical/source comparison.
