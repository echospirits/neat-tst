# External website links — v0.2 validation

Date: 2026-10-10. Development version: `0.2.0-dev`.

## Audit and scope

- Started from `staging/tst` at `650bbc0bfeb5442f25e79aaaa253b8f2d9373910` in an isolated worktree. Production baseline observed at `af1f396726e3b15e1167f5af2aa6ba426cae9bf9`.
- Reviewed application anchors, dynamic href producers, Next links and programmatic navigation. Five missing external-link targets were found: the shared account address anchor and four Shortcut installation/update anchors across setup, review (error and outdated-version states) and profile.
- Address links use `_blank` and `noopener noreferrer` for Google/Apple Maps. Android continues to use its `geo:` native-app handoff with `_self`. Shortcut install configuration accepts HTTPS URLs. Accessible link names announce the new tab.
- Existing contextual/directory Directions, research websites, cocktail menus, evidence/source URLs, operating-hours sources and menu-placement proof links already use `_blank` with `noreferrer`.
- Internal account/task/navigation links, exports/downloads, telephone/text/email protocols and `shortcuts://` execution keep their existing behavior. Google Calendar connect/reconnect is an intentional OAuth round trip through an internal route, so its authorization/callback flow is preserved.
- No CSS/layout, schema, migration, database contents, provider configuration, dependency, entitlement or production change.
