## Verification and fix

The current `app/tags/actions.ts` scoped LocationTag assignments to the caller's organization but accepted `tagId` without checking the Tag owner. `LocationTag.tag` references only `Tag.id`, so the database did not reject a foreign organization's tag. The wholesale creation path already filters tag IDs by organization, confirming the intended ownership boundary.

The action now calls `tag.findFirst` with both submitted ID and authenticated `organizationId`, selecting only the ID, before either upsert. A missing or foreign tag returns the same existing invalid redirect before any assignment write or cache refresh. Same-organization agency and wholesale paths preserve their unique keys, created-by metadata, note normalization, idempotent updates and account-specific revalidation.

No schema migration, production promotion, tag ownership transfer, data repair or temporary shared-TST session is included. A composite tenant-aware database relation and auditing historical assignments are separate follow-up work; this change closes the submitted-ID authorization gap in this action.
