## Behavior and migration

- Existing wholesale names remain unchanged on Account Master and target-workbook imports, including inactive accounts. New accounts receive their initial OHLQ name. `isActive` continues to mean shared-directory availability; it is no longer part of the name rule.
- Street address, city and ZIP have independent persistent protection flags. A manual change, including deliberate clearing, protects only that field. Other fields continue their prior import policy. New manually supplied address values are protected, including production's existing matched-account correction path.
- The backfill protects current differences from linked raw OHLQ Account records and populated fields on known user-created unlinked accounts, excluding merged tombstones. Divergence does not prove who edited a field. Previously overwritten corrections cannot be recovered from current records.
- Raw OHLQ records continue refreshing. Account Master resolves protected values inside a parameterized UPDATE against the locked current account; it never assigns an existing name or clears protection flags. Edits saved after import preflight survive. Protected blanks survive official relinking, target imports and account merges. Geocodes reset only when the resulting normalized public address changes.
- No new feature flag, entitlement, environment variable or provider credential is required. Agency imports and sales-status automation are outside this change. No live import or workflow dispatch was run during validation.
- Apply only `prisma/migrations/20261010160000_wholesale_address_import_protection/migration.sql`. It adds three non-null booleans with false defaults and backfills flags without changing existing account columns. Canonical SHA-256: `394ecc3492e7c86fb7f81ca580500cfdaaf7cf284bb5fc59a08eaab0477c23bd`. No broad migration deployment, schema push or reset is authorized by this patch.
