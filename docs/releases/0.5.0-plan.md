## Authorized scope

The owner also requested investigation and improvement of slow page navigation and account opening. Reduce avoidable server-side work and query waterfalls while preserving state and tenant access, existing account tabs, and field-workspace behavior. See [performance validation](0.5.0-performance-validation.md).

Implement the approved Schedule, Worklist, account, visit, and navigation refinements in the existing ivory/olive/sage system. On desktop, use consistent named account tabs instead of a stack of unrelated disclosures. Keep mobile actions reachable and contextual. Collapse optional evidence and setup; preserve edit/import/order/targeting/history capabilities and existing entitlements.

The briefing shows recorded facts only, a concise next action, and one empty summary when history is missing. Relationship-health scoring and provenance remain available as supporting evidence; missing data never becomes a healthy zero. Retired Communications, Support, Recipes, and standalone Deals/Activities stay retired.

No migration, backfill, new feature flag, provider activation, hosted configuration, or live data mutation is required. Existing canonical server actions, tenant restrictions, Worklist/calendar effects and physical-visit semantics remain authoritative.
