# Extended v0.2 implementation plan

Target lineage: 0.2.3-dev, then 0.2.3 only after a frozen candidate passes validation. Existing 0.2 artifacts remain immutable. Existing 0.2.0 security manifest entries are preserved.

1. Audit and permanent documentation.
2. Tenant-safe activity/integration infrastructure.
3. Gmail/Graph and communication matching/review.
4. Deals, relationship briefings and deterministic next actions.
5. SMS, playbooks, field tools, recipes and events.
6. Outcome reporting and optional AI.
7. Security, database/browser acceptance, build and TST release evidence.

The full brief remains the scope. Do not declare a release candidate complete based only on a foundation increment. Production approval and credential rotation are separate gates.

Communications is included as an Echo Spirits-only **Pilot** in v0.2: connected email/imported appointments, business SMS and reviewed contact suggestions require explicit COMMUNICATIONS enrollment. It is excluded from standard Core/Intelligence packages and from automatic TST enablement. Run the additive entitlement migration during the authorized v0.2 release; review [Echo's demo/live test guide](../product/communications-pilot-review.md) before any wider enrollment. Ordinary Contacts, Log Visit, phone/email initiation and Worklist calendar sync remain canonical Core functionality.
